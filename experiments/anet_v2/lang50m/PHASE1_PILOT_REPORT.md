# Phase 1 pilot 报告：领域比例与 batch/boundary 混合

- 分支：experiment/anet-v2
- 数据：30M math bytes + 30M code bytes（byte-level）
- 训练：每 run 6M tokens；batch=16，seq=128，AdamW，FP32
- 模型：Transformer-12L vs Shared-Depth A-Net
- 运行数：2 架构 × 5 比例 × 2 模式 × 1 seed = **20 runs**
- 状态：pilot；不是最终能力结论

## 1. 参数与资源

| 模型 | 唯一参数 | 单次激活参数 | 激活 FLOPs/token |
|---|---:|---:|---:|
| Transformer-12L | 37,503,168 | 37,503,168 | 40,591,360 |
| Shared-Depth A-Net | 50,177,024 | 37,501,632 | 40,591,360 |

- 两者深度 12、激活参数差 1,536（0.0041%）、激活 FLOPs 相同。
- 训练峰值显存约 1.32–1.84 GB；单 run 训练约 160–210 秒。
- 20 个 run 总训练时间约 65 分钟。

## 3. 主要观察

1. **混合比例下 A-Net 在两个域都略好**：
   - 75% math：math -0.014、code -0.248 BPC；
   - 50% math：math -0.034、code -0.168；
   - 25% math：math -0.016、code -0.148。
2. **纯数学比例下 A-Net 数学更差**：1.172 vs 1.044；A-Net 没有在单一数学任务上超过 Transformer。
3. **纯数学训练时 code BPC 不可解释**：A-Net 8.139 vs Transformer 17.579，但两者 code 任务头都没训练；这不是代码能力优势。
4. **batch 内混合 vs boundary 切换差异很小**：本预算/单 seed 下没有明显分离；最大差异约 0.04 BPC。
5. **Transformer 在 100% math 的 code 头严重过拟合/失配**（17.579），不能作为架构优劣结论。
6. **A-Net 训练略快/显存略高**：训练时间与 Transformer 接近；峰值显存 1.65–1.84 GB vs 1.59–1.61 GB（A-Net 略高）。
7. **next-byte accuracy 与 BPC 趋势一致**，但这仍不是数学答案准确率。

## 4. 训练-测试 gap

报告原始 JSON 中有 train_test_gap_bpc（val BPC − train BPC）。由于 6M tokens/单 seed，gap 噪声较大，未用于结论。需要 3 seeds 后才能解释。

## 5. 不能下的结论

- 不能说明 A-Net 在数学/代码“能力”上超过 Transformer；
- 不能说明 batch 内混合与 boundary 切换有显著差异；
- 不能外推到 30M/60M BPE tokens 或更大模型；
- 不能替代 MMLU/GSM8K/HumanEval；
- 不能证明 Lα 特征分解或 Lω 整合有效（尚未实现）。

## 6. 结论

Phase 1 pilot 跑通，并出现一个值得继续验证的趋势：

> 在混合数学/编程数据下，Shared-Depth A-Net 在两个域的 BPC 都略低于同深度/同激活参数的 Transformer-12L；但在纯数学数据上 A-Net 更差。

这只是 **1 seed、6M tokens/run** 的 pilot，不是最终结果。下一步应：

1. 加 3 seeds；
2. 增加 token 预算；
3. 实现数学答案准确率和代码可解析率；
4. 补 Lα/Lω 消融后，再做正式 60M-token 实验。
